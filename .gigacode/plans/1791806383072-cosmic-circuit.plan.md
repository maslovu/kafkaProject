# План рефакторинга kafkaProject

## Критические исправления (обязательные)

### Step 1: Исправить `mainClass` в parent pom.xml
**Файл:** `pom.xml` (строка ~109, внутри `<pluginManagement>`)
- **Было:** `<mainClass>com.maslov.app.ConsumerApplication</mainClass>`
- **Стало:** `<mainClass>com.maslov.ConsumerApplication</mainClass>`
- **Риск:** LOW. App module уже переопределяет это, но значение в `pluginManagement` должно быть корректным.

### Step 2: Исправить `spring-boot-starter-aop` scope
**Файл:** `pom.xml` (строка ~53)
- **Было:** `<scope>provided</scope>`
- **Стало:** убрать `<scope>` (compile по умолчанию)
- **Почему:** Resilience4j использует AOP для `@CircuitBreaker`, `@Retry`, `@Bulkhead`, `@TimeLimiter`. Без AOP в runtime аннотации не сработают.
- **Риск:** LOW.

### Step 3: Исправить `ErrorHandlingDeserializer` — возвращать правильный объект
**Файл:** `KafkaBatchConsumerConfig.java` (метод `getObjectJsonDeserializer()`)
- **Было:**
```java
ErrorHandlingDeserializer<CommentEvent> errorHandlingDeserializer =
        new ErrorHandlingDeserializer<>(jsonDeserializer);
return jsonDeserializer; // ❌ Возвращается обычный JsonDeserializer!
```
- **Стало:**
```java
ErrorHandlingDeserializer<CommentEvent> errorHandlingDeserializer =
        new ErrorHandlingDeserializer<>(jsonDeserializer);
return errorHandlingDeserializer; // ✅
```
- **Почему:** Без этого битый JSON упадёт консьюмер, а не обработается ErrorHandlingDeserializer.
- **Риск:** MEDIUM.

### Step 4: Исправить `MAX_POLL_INTERVAL_MS_CONFIG`
**Файл:** `KafkaBatchConsumerConfig.java` (метод `consumerFactory()`)
- **Было:** `props.put(ConsumerConfig.MAX_POLL_INTERVAL_MS_CONFIG, 5000);` // 5 секунд
- **Стало:** `props.put(ConsumerConfig.MAX_POLL_INTERVAL_MS_CONFIG, 300000);` // 5 минут
- **Почему:** 5 секунд гарантируют ребаланс при обработке 50 записей + HTTP-вызов.
- **Риск:** LOW.

### Step 5: Исправить отправку null в DLT при ошибке десериализации
**Файл:** `CommentConsumerService.java` (блок try-catch внутри for-цикла)
- **Было:** `event = record.value();` (выбрасывает исключение), потом `kafkaTemplate.send(dltTopic, record.key(), event);` где `event == null`
- **Стало:** вынести `event` внутрь try, отправить `null` явно с комментарием:
```java
try {
    CommentEvent event = record.value();
    events.add(event);
} catch (Exception e) {
    log.error("Error processing message at index {} for key {}", i, record.key(), e);
    dlqMessagesCounter.increment();
    String dltTopic = record.topic() + ".DLT";
    kafkaTemplate.send(dltTopic, record.key(), null);
    log.info("The message with key {} has been successfully isolated into DLT topic {}", record.key(), dltTopic);
}
```
- **Почему:** `event` остаётся null при исключении, `JsonSerializer` не может сериализовать null.
- **Риск:** MEDIUM.

### Step 6: Исправить `Client.Default(null, null)` — включить SSL
**Файл:** `CommentClientConfig.java` (метод `client()`)
- **Было:**
```java
return new Client.Default(null, null) { };
```
- **Стало:**
```java
import java.security.NoSuchAlgorithmException;
import javax.net.ssl.SSLContext;

// ...

try {
    SSLContext sslContext = SSLContext.getDefault();
    return new Client.Default(sslContext.getSocketFactory(), null);
} catch (NoSuchAlgorithmException e) {
    throw new IllegalStateException("Failed to initialize Feign client with default SSL context", e);
}
```
- **Почему:** `null` truststore + `null` hostname verifier = MITM-атаки возможны.
- **Риск:** MEDIUM. В тестах используется HTTP (WireMock), поэтому не сломает тесты.

### Step 7: Использовать `httpScheduler` в `ExternalApiSender`
**Файл:** `ExternalApiSender.java`
- Добавить поле `private final Scheduler httpScheduler;`
- `@RequiredArgsConstructor` автоматически создаст конструктор для нового final-поля
- Передать scheduler в `supplyAsync`:
```java
return CompletableFuture.supplyAsync(() -> {
    ResponseEntity<Void> response = commentClient.sendCommentsBatch(batch);
    log.debug("Batch send response status: {}", response.getStatusCode());
    return null;
}, httpScheduler);
```
- **Почему:** ForkJoinPool.commonPool() делится с другими async-операциями.
- **Риск:** LOW.

### Step 8: Обработать `ResponseEntity<Void>` в `ExternalApiSender`
**Файл:** `ExternalApiSender.java` (внутри `send()`)
- Присвоить результат вызова клиента в переменную и логировать статус
- **Риск:** LOW.

**Файл:** `CommentConsumerService.java`

```java
private void sendToDlt(String topic, String key, CommentEvent event) {
    try {
        String dltTopic = topic + ".DLT";
        kafkaTemplate.send(dltTopic, key, event);
        log.info("Message with key {} isolated into DLT topic {}", key, dltTopic);
    } catch (Exception dltEx) {
        log.error("Critical error sending key {} to DLT: {}", key, dltEx.getMessage());

}
```
